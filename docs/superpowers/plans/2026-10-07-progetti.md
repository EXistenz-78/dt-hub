# Gestione dei progetti — Piano di implementazione

> **Per chi esegue:** SOTTO-SKILL OBBLIGATORIA: `superpowers:subagent-driven-development` (consigliata) oppure `superpowers:executing-plans`. I passi usano la sintassi a caselle (`- [ ]`).

**Obiettivo:** il progetto come sottocartella della cartella di output, con il suo stato di Control, la striscia dei risultati e lo stato dei plug-in; apertura con parametri dall'ultima immagine.

**Architettura:** logica e stato in HubCore (`Projects/`: nome, catalogo, stato legacy, ultima immagine, `ProjectManager`), testati con `swift test`; `ControlStore` e `GenerationSession` diventano ricollegabili a un altro progetto; un messaggio nuovo `project` verso i plug-in (aggiunta compatibile al contratto 1); nell'app solo collegamento, un menu nella `HeaderBar` e due fogli.

**Tecnologie:** Swift 6.2, Swift Testing (`import Testing`, `@Test`, `#expect`), SwiftUI/AppKit, `FileManager`, `UserDefaults`.

**Spec:** `docs/superpowers/specs/2026-10-07-progetti-design.md` (leggerla prima: cartelle §3, regole del nome §4, messaggio ai plug-in §5.5).

## Vincoli globali

- Base: `origin/main` (0.1.1). Ramo nuovo (es. `progetti`). **Non si unisce in `main` e non si fa push/release senza «unisci»/via libera esplicito dell'utente.**
- Si aggiungono i file **per nome** (`git add <file>`); mai `git add -A` né `git add docs`.
- Test di logica: `cd Packages && swift test --filter <Suite> 2>&1 | grep -E "Test run with|error:"`. Test di un plug-in: `cd Plugins/<P> && swift test 2>&1 | grep -E "Test run with|error:"`.
- I test che toccano `@MainActor` (`ProjectManager`, `ControlStore`, `GenerationSession`, `PluginRegistry`) vanno marcati `@MainActor`; niente `UserDefaults.standard` nei test (si usa un'astrazione in memoria o una suite con nome unico).
- Chi cambia `ControlStore`, `GenerationSession` o `ImageStore` deve compilare anche l'app: `xcodebuild -project DTHub.xcodeproj -scheme DTHub -destination 'platform=macOS' -derivedDataPath build build`.
- Testi dell'interfaccia in italiano e inglese (`Localizable.xcstrings`, `extractionState: manual`, entrambe le lingue `translated`). Plug-in: tabella `L` con le due lingue. Commenti nel codice in inglese.
- Dopo l'unione in `main` (solo con «unisci»): ricompilare l'app dell'utente (comando sopra) e dirgli di riavviarla; reinstallare i plug-in aggiornati con la procedura del briefing (`rm -rf` della vecchia versione prima di `cp -R`).
- Nei testi pubblici non si dice che DT Hub «sostituisce» l'interfaccia di Draw Things.

## Review Focus

Casi che la spec implica e nessun test «felice» esercita; ognuno ha il suo test nel task indicato.

1. Cambio progetto durante un RUN, la preparazione o una pipeline: rifiutato, niente stato a metà (Task 7).
2. Progetto senza immagini, o ultima PNG cancellata/illeggibile: parametri di default, nessun crash (Task 4, Task 9).
3. Nome del progetto con `/`, `:`, punto iniziale, forma di data, duplicato con altre maiuscole o accenti (Task 1).
4. Il progetto corrente cancellato dal Finder mentre l'app è aperta, o cartella di output cambiata: `current = nil`, foglio di scelta, RUN bloccato (Task 7, Task 9).
5. Plug-in che non capisce `project`, o `state.json` corrotto: stato iniziale e una sola nota, mai un errore (Task 8, Task 10–12).
